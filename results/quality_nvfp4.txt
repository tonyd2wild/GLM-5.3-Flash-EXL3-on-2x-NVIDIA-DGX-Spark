# Part 1: Top K Frequent Elements

```python
import heapq
from collections import Counter

def top_k_frequent(nums, k):
    """
    Return the k most frequent elements in nums.
    Time: O(n log k), Space: O(n) for the counter.
    """
    if k <= 0 or not nums:
        return []

    counts = Counter(nums)  # O(n)

    # Min-heap of size k: (frequency, element)
    heap = []
    for num, freq in counts.items():  # O(m) distinct elements, m <= n
        heapq.heappush(heap, (freq, num))
        if len(heap) > k:
            heapq.heappop(heap)  # evict least frequent

    return [num for freq, num in heap]
```

**Why O(n log k):** Counting frequencies is O(n), and there are at most n distinct elements, each of which triggers at most one push and one pop on a heap capped at size k — each heap operation costs O(log k), giving O(n log k) total. This beats sorting all frequencies (O(n log n)) because the heap never grows beyond k. **Edge case handled:** if `k` is zero/negative or `nums` is empty, it returns an empty list instead of erroring.

# Part 2: Bat and Ball

Let the ball cost **b** and the bat cost **b + 1.00**.

$$b + (b + 1.00) = 1.10$$
$$2b + 1.00 = 1.10$$
$$2b = 0.10$$
$$b = 0.05$$

Check: ball = $0.05, bat = $1.05, total = $1.10 ✓ (and the bat is $1.00 more than the ball ✓)

ANSWER: $0.05
